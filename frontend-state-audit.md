# Frontend state machine audit

Application Station's `index.html` and `wordcraft-demo.html` share the same app logic. This audit covers the working-tree frontend, its storage and async dependencies, and the checked-in WordCraft bridge. Each entry identifies the state variables, the valid subset of their Cartesian product, and how the implementation can reach a conflicting state. Source links refer to the working tree at the time of the audit.

The original audit was static. The Node suite passed 86 tests and the standalone runner passed. The browser integration suite was not run. Findings involving interleavings, browser behavior, or injected failures need reproduction before a fix is accepted.

## Generation and storage

| Machine | Variables and valid combinations | Conflicting transitions |
| --- | --- | --- |
| Generation coordinator | `isRunning`, invocation phase, run kind, worker count, claimed IDs, completed/total, editor pause. Idle has no owner. Starting and finishing retain ownership. Running has one selected worker or up to two batch workers, with one owner per job. | Two starts can cross awaits before either sets `isRunning`. Either cleanup can unpause the other. Batch `Promise.all` can release ownership on rejection while a worker continues. Workers consume a live queue against a fixed total. [Start and workers](main.js#L2326) |
| Per-job generation and commit | Eight statuses, result/resume/details keys, generated mode, recommendation, counts, diagnostic lists, runtime error, backup flags. Normal path is queued/retry → preparing → tailoring → applying → done/partial, with failed on error. Restore maps in-flight statuses to retry. A committed result's blobs, details, and metadata belong to one attempt. | Terminal status precedes separate artifact writes. A write failure or overlapping snapshot can expose mixed or missing artifacts. A failed rerun can leave old bytes under failed status. A read that throws before the job's try block can strand a batch claim in preparing. A guarded exit can downgrade a job while retaining old results. [Status normalization](main.js#L424) · [Artifact writes](main.js#L1937) · [Run](main.js#L2075) |
| Generation inputs | Base/resume revisions, sample set, key, model, prompt settings, mode, comments, job metadata. A coherent attempt uses one snapshot. The raw product permits each stage to see a different version. | Uploads and setting changes can split worker inputs. A mode change can produce different modes for the prompt, letter, resume, repair, and stored label. Comment inclusion is read after the request. [Inputs and apply](main.js#L2095) |
| Source and sample uploads | Filename, parsed paragraphs, blob, draft, epoch, sample list and blob references, drop highlighting, file input value. A stable slot is absent or has matching metadata and bytes, including valid zero-paragraph documents. Samples reference existing blobs. | Replacements can complete out of order and interleave blob, epoch, and metadata writes. Add and Clear Samples can overlap. Failure on a later sample can leave earlier writes unreflected in the UI or snapshot. Rejected uploads skip input reset. A child dragleave can clear highlighting prematurely. [Sources and samples](main.js#L1582) · [Drop zones](main.js#L2505) |
| Session restore, removal, and reset | Store/backend and phase, snapshot, live metadata, referenced blobs, outstanding writes. Opening → restoring → ready → resetting. Stable snapshots reference available artifacts and a valid selection. | Handlers are wired before restore ends. Clear Applications can remove jobs during generation and detached workers can write afterward. Individual removal checks running only before its flush. Restore trusts completed status without checking result bytes. Reset reloads on blocked or failed database deletion. [Restore](main.js#L1214) · [Reset](main.js#L1554) · [Removal](main.js#L1740) · [Startup](main.js#L2875) |
| Accept and Undo | Result, draft, tracked changes, mode/count, backup flag/blob, epoch. A backup flag and blob have four raw combinations. Only both present for the current generation or both absent agree. Undo restores that generation's backup and clears it. | The flush lock ends before writes. Accept/Undo can overlap with editing, regeneration, deletion, and each other. An intervening draft can become stale after replacement. Reruns clear flags before success and can leave backup blobs behind. Historical operation count can keep Accept visible when no revisions remain. [Eligibility](main.js#L830) · [Actions](main.js#L1811) · [Rerun](main.js#L2105) |
| Export | Scope, captured job IDs and result/draft revisions, entry paths, archive phase. Valid path is flush → read coherent results → build → download, or stop with empty/error. Distinct files need distinct entry paths. | Reads can straddle generation or mutation. Bulk eligibility checks status, then reads every job with a letter blob, including stale failed outputs. Duplicate normalized company/role/month names can replace archive entries while the success count includes both. [Names](main.js#L400) · [Export](main.js#L2439) · [Archive](docx-engine.js#L726) |

## Selection and editing

| Machine | Variables and valid combinations | Conflicting transitions |
| --- | --- | --- |
| Job selection, creation, and metadata | Jobs, selected ID, editing ID, add/edit input values, saved company and role. Raw IDs can be null, live, or stale. Selection and a visible form should belong to live jobs. | A click can apply a captured ID after removal. Retry changes selection before rendering the matching preview and may stop at a run guard. Switching/removing can strand an edit ID. Full rerenders reset unsaved form fields. Two Add clicks can read the same text before either clears it. [Add](main.js#L1686) · [Form](ui.js#L311) · [Selection](main.js#L2830) |
| Preview target and renderer | Selected ID, type, source/result key, blob/draft, engine, request version, host, status. Each tab may show its result, its source, or an empty state. The raw product permits any target with any host content. | Standard rendering writes directly to the shared host before the final version check. The WordCraft empty branch writes after an awaited clear without rechecking. Resume eligibility uses filename/count as a proxy for bytes. Initial reads can reject outside preview recovery. [Eligibility](main.js#L1159) · [Dispatch](main.js#L1418) · [Host write](docx-engine.js#L683) |
| Editing mode and iframe | Mode, change flag, saved preference, checkbox/HTML attribute, module promise, registry entry, ready state, lock count, disabled flag, inertness. Stable modes are standard with no editor or WordCraft enabled with an empty target or ready editor. A ready iframe is inert while locked or paused. | Generation can start while mode is changing. Open and clear can retain an obsolete iframe across awaits. Startup's bridge polling deadline begins after an initial HEAD request with no app-level timeout. [Toggle](main.js#L83) · [Startup](wordcraft-preview.js#L153) · [Teardown](wordcraft-preview.js#L285) |
| WordCraft binding and drafts | Queue, active key/job/type/hash, native document ID/revision/dirty, saved revision, epoch, draft record. Valid states include unbound, bound clean/dirty, saving, and foreign document. Only matching identity may save. Effective drafts match source hash and epoch. Native clean can still mean app-dirty after File Save. | Clean foreign documents can be released by tab/card navigation but block stricter actions, and Retry Saving cannot reconcile them. Separate source/epoch reads and writes, read-modify-write increments, and tab-local queues allow lost updates and stale drafts. [Session](wordcraft-session.js#L6) · [Epoch](wordcraft-drafts.js#L17) |
| Autosave, retry, and unload | Last observation, pending local edit and timestamp, schedule revision and timestamps, saving flag, retry time, visibility, locks, error state. Both dirty schedule timestamps are absent when clean and present when dirty. Dirty → due → snapshot → store → acknowledge or back off. | Cached unload state and heuristic input capture can miss native edits or a foreign file change between polls. A timed-out RPC may still execute, so a late load can replace the document while the parent retains the previous binding. Pause/resume can clear a displayed save error. [Guard and schedule](wordcraft-preview.js#L6) · [Polling](wordcraft-preview.js#L192) · [Bridge](vendor/wordcraft-patches/compact-startup.patch#L173) |

## Credentials and supporting UI

| Machine | Variables and valid combinations | Conflicting transitions |
| --- | --- | --- |
| API-key validation | Input, saved key, validation fingerprint/time, pending flag, request key/model, selected model. Empty, unvalidated, pending for a snapshot, validated for that snapshot, and failed/unavailable are distinct states. | Saving or clearing B during A's request can skip B's validation and let A overwrite storage. Model changes can stale the status. Partial fingerprints can match different keys. Failed revalidation retains a prior marker. Generate is enabled for a nonempty key even when its handler will refuse the run. [Fingerprint](main.js#L597) · [Validation](main.js#L1122) · [Save](main.js#L2737) |
| Requests and dependency loading | Attempt 1–3, controller/timer, response/error, backoff, terminal result. DOCX engine cache is empty, pending, fulfilled, or rejected. | A failed document request leaves its sibling running. Fetch timeout does not cover downstream body parsing. A cached engine import rejection persists until reload. [Retries](cover-letter-ai.js#L167) · [Parallel calls](main.js#L2139) · [Imports](docx-engine.js#L288) |
| Tailoring source cache | Bounded ordered map with key, hash, bytes, promise, paragraphs, initial document and claim flag. Absent → preparing → unclaimed → claimed. The first caller can claim the prepared document, and later callers get independent copies. | A slow old hash can replace a newer cache entry. Clear can race with a pre-insertion hash. The observed effect is extra parsing because each caller retains its own entry and checks its own input hash. [Cache](tailoring-source-cache.js#L12) |
| Welcome, Settings, checklist, and tour | Welcome seen/visible, Settings visible, checklist dismissed/forced/expanded/toast flags and four progress bits, active tour, index, listeners and callbacks. Settings and checklist can coexist. | Forced open is ignored by visibility, so completed setup cannot reopen. Global Escape persists dismissal even if the checklist is hidden or the tour handles Escape. Tour callbacks can survive teardown. [Checklist](main.js#L936) · [Escape](main.js#L2714) · [Tour](tour.js#L120) |
| Menus, preferences, and disclosures | Menu visibility/ARIA and eligibility, theme, mode, comments, model/guidance, disclosure open/hidden/job owner. Three of four menu visibility pairs are valid. ARIA follows visibility. Theme and mode each normalize to two values. A hidden disclosure can preserve its open choice for the same job. | Menu can stay open when its trigger becomes disabled. Saved and live preferences can diverge on storage failure or across tabs. No independent disclosure dead end found. [Controls](main.js#L830) · [Preferences](main.js#L2651) · [Disclosures](ui.js#L345) |
| Sidebar | Compact/wide, applied/stored/ARIA width, drag origin, listeners, resizing class. Compact has no inline width. Wide is idle with bounded width or dragging with one owner. | Cleanup only handles pointerup. Cancellation can strand resize state. A second pointer or layout change can move or finish the wrong gesture. [Sidebar](main.js#L719) |
| Feedback | Progress class/visibility/unit/label/count, toast visibility/timer, mascot mood/bubble/timer, pulse class/timer. Visible progress has one owner and one unit. Timer replacement should clear only its own feedback. | Toast/mascot/pulse ordinarily cancel older timers. Parallel workers overwrite the progress label, repair changes units, and unrelated status updates can hide active progress. [Feedback](ui.js#L124) · [Mascot](main.js#L223) · [Repair](main.js#L1989) |
| Version navigation | Link busy, run state, editor binding, flush outcome, navigation. Idle → saving → navigate or back to idle. Modified click leaves the current editor in place. | The run guard is checked before an awaited flush. Generation can start during that wait and navigation can still discard the page. [Version link](main.js#L2569) |
